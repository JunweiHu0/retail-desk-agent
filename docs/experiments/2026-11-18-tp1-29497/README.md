# 2026-11-18 · TP=1：显存装不下，实验终止

想验证"去掉 TP=2 的每层 all-reduce 能不能降 TPOT"。结论在跑压测之前就确定了：
**单卡放得下模型，但放不下可用的 KV cache。**

| 配置 | 权重+缓冲占用 | 可用 KV |
| --- | --- | --- |
| TP=2（课程默认，每卡） | 9.27 GiB | **10.24 GiB** |
| TP=1（单卡） | **18.36 GiB** | **0.18 GiB** |

（max-model-len 8192，gpu-memory-utilization 0.90，24 GB 卡）

## 0.18 GiB KV 意味着什么

按 TP=2 的数据反推：32,768 token 对应 10.24 GiB → 约 **0.32 MB/token**。

```
0.18 GiB ÷ 0.32 MB/token ≈ 570 token
```

而压测和 agent 的 prompt 是 **5,284 token**，需要约 1.7 GiB KV。
**连一个请求都放不下**，因此没有跑压测，直接终止。

## 为什么权重是 18.36 GiB 而不是 14 GB

INT4 量化只压缩了线性层；embedding 和 lm_head 通常保留 bf16，再加上反量化缓冲、
CUDA graph、编译 workspace，单卡实占比"14 GB 权重"高约 4 GiB。

## 结论

1. **TP=2 不是性能偏好，是硬约束**：24 GB 卡上，TP=1 无法提供可用上下文。
2. 因此"去掉 all-reduce 提速"这条路在本硬件上不可行；除非换更大显存的卡。
3. 同理，**DP=2 副本（每卡一个 TP=1 实例）也不可行**——每个副本都需要 18.36 GiB + KV。

这条反过来解释了课程默认配置为什么是 TP=2。

# 登录、个人资料和订单管理

访问 http://localhost:8000 ，使用登录页的演示客户按钮填入账号，再点击登录。

- 示例邮箱：`li.ming@retail-demo.example.com`
- 六个内置模拟客户的演示密码：`Demo@Retail2026!`
- 也可以注册新账号；新账号没有历史订单或支付方式，不会继承其他客户的数据。

工作台顶部提供客服助手、订单管理、个人信息。订单支持搜索、状态筛选、商品、收货地址、付款/退款和物流记录。待处理订单可以发起取消、地址和支付方式变更，已送达订单可选择商品退货；商品规格变更和换货可从“咨询此订单”交给 Agent。

订单页与资料页发起的变更通过同一套 RetailService 工具生成预览。点击“查看变更明细并处理”进入客服中的确认卡片；只有点击“确认执行”才会原子写入 SQLite 并保存审计。取消操作不会变更业务数据。聊天中的普通“是”不能代替确认按钮。

登录身份由后端绑定到 Agent，会话和订单接口都检查所属用户。登录后的 Agent 无需再次索要邮箱核验，也不能通过查询其他邮箱切换客户。历史对话保存在服务端，退出登录后再次登录可以继续查看；之前的匿名咨询不会自动归到任何账号。

密码采用随机盐 PBKDF2-SHA256（600000 次），登录 cookie 为 HttpOnly / SameSite=Lax，服务端仅保存登录 token 哈希，有效期 12 小时，退出会撤销。HTTPS 下启用 Secure cookie；写接口检查 Origin，错误登录按 IP 与邮箱限制。内置账户仅用于本地合成数据演示，可设置 `DEMO_ACCOUNTS=0` 禁止自动创建（已有账户需管理员单独管理）。模型 API Key 仍只在后端本地 `.env`。

验证：后端 37 项测试覆盖身份隔离、token 撤销、登录限流、注册防接管、订单预览与重复确认；桌面 Playwright 3 项覆盖登录、资料、订单确认、Agent 联动、账号切换、地址取消、新注册账号。浏览器测试必须使用独立临时数据库及 `AGENT_MODE=demo`，因为测试会确认取消测试订单。真实模型只做只读查询检查，需显式运行 `node e2e/deepseek-live.mjs --run-live`。
